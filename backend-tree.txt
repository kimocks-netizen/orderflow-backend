## Layered Architecture

```
Request → Routes (HTTP + validation) → Services (business logic) → Repositories (raw SQL) → SQLite
```

### Routes (app/routes/)
  - Parse request params/body
  - Pydantic schema validation (automatic via FastAPI)
  - Call service layer
  - Return response with appropriate HTTP status

### Services (app/services/)
  - Business rules: status transition validation, auth logic
  - Orchestrate repository calls
  - Raise domain exceptions (NotFoundError, ValidationError)
  - No HTTP or SQL knowledge

### Repositories (app/repositories/)
  - Raw SQL queries (sqlite3)
  - Cursor-based pagination logic
  - Dynamic filter building
  - Return dicts/lists — no domain logic

## Key Patterns

### Cursor-Based Pagination (order_repository.py)
  Composite cursor: created_at + id
  SQL: WHERE (created_at, id) < (?, ?) ORDER BY created_at DESC, id DESC LIMIT ?+1
  Fetch limit+1 rows → if extra row exists, has_more=True
  Response: { items, next_cursor, has_more }

### Status Transitions (order_service.py)
  ALLOWED_TRANSITIONS dict defines valid moves
  Atomic UPDATE: WHERE id = ? AND status = ? (prevents race condition)
  rows_affected == 0 → NotFoundError or ConflictError

### Auth (core/security.py)
  JWT encode/decode using python-jose
  get_current_user: FastAPI Depends() extracts user from Bearer token
  Single admin user — no RBAC complexity

### Error Handling (errors/exceptions.py + middleware/error_handler.py)
  Custom exception hierarchy: AppError → ValidationError, NotFoundError, etc.
  Global exception handler catches AppError → returns { "detail": message } + status code
  Pydantic validation errors → 422 (automatic by FastAPI)

### Config (core/config.py)
  pydantic-settings loads from .env
  Fields: database_path, jwt_secret, jwt_algorithm, jwt_expire_minutes
  @lru_cache() singleton

### Database (database/connection.py)
  sqlite3 connection with WAL mode + foreign keys enabled
  FastAPI dependency: def get_db() yields connection
  Migrations auto-run on startup via lifespan event
